# Para! promo video (60 seconds)

A Remotion project that builds `out/para-demo-60s-16x9.mp4` (1920x1080) and `out/para-demo-60s-9x16.mp4` (1080x1920) from real recordings of the app. It has its own `package.json`; nothing in the app or the root `package.json` was changed.

## What is real and what is added

- **App footage is recorded, never drawn.** `capture.mjs` builds the app twice from the same commit, serves each build with `vite preview`, drives it with `puppeteer-core` (through `scripts/lib/browser.mjs`), cuts the network, and saves the browser's own screencast frames at 1170x2532 (390x844 at device scale 3).
- **Every station, fare, date and proof number in the video is read from the capture** (`footage/*.json`, field `facts`). None is typed into the video code. If the app's answer changes shape, the render stops with an error instead of showing something stale.
- **Added on top:** the phone and laptop frames, captions, titles, Tsupher sprites from `public/mascot/`, the cards that repeat captured text, the amber rings on the two tapped stations, and the "SAMPLE DATA" ribbon. All of that text is in `src/script.ts`.
- **Playback speed varies.** Typing and waiting are sped up, and in the trip clip the wait for the simulated trip is skipped (the video says "Nilaktawan ang paghihintay"). Nothing is reordered within a clip.
- No voice feature, no model output and no route planning is shown for the real build. The chat answer comes from the app's rules and templates; the thinking indicator did not appear in the capture, so it is not in the video.

## Capture

Needs Chrome or Edge (set `CHROME_PATH` if it is not in a default place) and the root `npm install`.

```sh
node video/capture.mjs              # builds REAL and SAMPLE into video/.build/, then records
node video/capture.mjs --no-build   # record again from the existing builds
```

The script stops if the working tree is dirty outside `video/` or if `HEAD` does not contain commit `33a093a`. It takes a few minutes. Station pair and chat wording are chosen by the script from what the app accepts (see `PAIRS` and `phrasings` at the top and middle of the file), then saved in the clip files.

Your own recordings can go in `footage/manual/`. Nothing reads that folder yet: add a layer in `src/Video.tsx` to use one.

## Preview and render

```sh
cd video
npm install
npm run sfx        # writes the three UI sounds to src/sfx/ (already there after the first run)
npm run studio     # Remotion Studio: scrub both compositions
npm run render     # both videos and out/poster-16x9.png
```

- Exact length: the picture is 1800 frames (60.000 s), but AAC audio is stored in fixed blocks, so a fresh render reports 60.011 s. To make the file exactly 60.000 s, shorten the audio by one block (run for each file, then replace the original):
  `npx remotion ffmpeg -y -i out/para-demo-60s-16x9.mp4 -t 59.97 -i out/para-demo-60s-16x9.mp4 -map 0:v -map 1:a -c copy -movflags +faststart out/tmp.mp4`
- Frame rate: `FPS` in `src/config.ts` (30). Set it to 60 and render again; all timings are in seconds.
- Words: `src/script.ts`. Timings and layout: `src/Video.tsx`. Springs: `src/springs.ts` (snappy, smooth, bouncy).
- After a new capture, check the scenes in the Studio: clip timings follow the saved marks, but a much longer or shorter recording can need a nudge in `KEYS`.
